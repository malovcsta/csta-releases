# CSTA: выпуски

Установщики CSTA для обновления через Manager.

Каждый установщик опубликован вместе с файлом подписи `CSTA-Setup-<версия>.exe.manifest.json`. Перед установкой Manager проверяет подпись, версию, размер и контрольную сумму файла. Для установки с флешки скачайте оба файла и положите их рядом.

Исходного кода в этом репозитории нет.

# Что изменилось

## 1.0.15

- Исправлен запуск встроенной базы данных на Linux.
- На экранах ЖД статики, погрузки/разгрузки и динамики вес больше не остаётся на табло, если сервер не отвечает или весы перестали передавать показания: через одну-две секунды вместо цифр прочерки, фиксация недоступна, а на экране указана причина. Когда связь вернётся, вес снова показывается.
- Экран ЖД статики нагружает сервер и компьютер оператора в несколько раз меньше. Свёрнутая вкладка ЖД-экрана не обращается к серверу.
- Если неизвестно, выполнилась ли команда, предупреждение остаётся на экране, пока его не закроют, а состояние станции сразу перечитывается с сервера. Такие предупреждения не вытесняются новыми и не пропадают при окне «Нет связи».
- Ошибка загрузки журнала сессии или поиска в справочнике показывается как ошибка, а не как пустой список. Если журнал сессии не загрузился, завершение сессии спрашивает подтверждение.
- Отмена сессии в карточке аварии ЖД статики требует подтверждения.
- Сбой одного блока экрана взвешивания, например камер или журнала, больше не закрывает весь экран: вместо блока сообщение, остальное работает.
- Если изображение камеры застыло, панель показывает «Камера недоступна» и переподключается. Миниатюра камеры при ошибке снимка больше не выдаёт старый кадр за живой.
- При временной ошибке сервера список станций не пропадает и оператора не уводит на «Дашборд»: страница показывает ошибку и повторяет запрос.
- В поиске контрагентов и лиц список больше не подменяется результатами предыдущего запроса.
- При смене фильтров отчёта сервер прекращает собирать прежний предпросмотр.
- Ключ доступа к изображениям камер больше не передаётся в адресе и не попадает в журналы.
- Исправлены известные ошибки веб-интерфейса: слишком длинный вес больше не обрезается на табло, окно завершения сессии ЖД динамики при ошибке не закрывается, скачивание файлов не обрывается в некоторых браузерах.
- Удаление программы больше не затрагивает базу данных, резервные копии, лицензию, логи и настройки: удаляются только файлы самой программы.
- Перед обновлением служба и встроенная база останавливаются штатно. Если файл программы занят, обновление не оставляет программу наполовину заменённой: возвращается прежняя версия и служба запускается снова.
- После обновления сервер сам выходит из режима обслуживания, входить в Manager и нажимать «Проверить» больше не нужно.
- Если установщик отказался работать, например уже запущен другой, обновление в Manager сразу отмечается как невыполненное, а не ждёт ручного завершения.
- При долгом обновлении базы Manager показывает, что сейчас происходит, и не прерывает ожидание через три минуты.
- В Manager появилась аварийная остановка службы на случай, когда служба не отвечает. Действие записывается в журнал обслуживания.
- Manager обращается только к своей службе на этом компьютере и не отправляет пароль на другие адреса.
- Ручное включение выхода модуля ввода-вывода в Manager требует подтверждения. Выход выключается сам через 30 секунд, при уходе с формы и при закрытии Manager.
- Сохранение оборудования в Manager не стирает настройки станций, заданные в веб-интерфейсе. Ошибка в файле конфигурации показывается с указанием поля.
- Пока служба работает, Manager берёт состояние весов, считывателей и модулей у неё и не мешает её подключениям к оборудованию.
- Ошибка в окне Manager больше не закрывает программу: показывается её текст.
- Лаунчер запоминает свой сервер и находит его после смены адреса. Если в сети несколько серверов, лаунчер предлагает выбрать.
- При потере связи лаунчер показывает страницу «Нет связи с сервером» и сам возвращается, когда сервер снова доступен. Клавиша F5 обновляет страницу.
- Данные лаунчера больше не теряются при очистке временных файлов Windows.
- Сервер можно установить службой на Linux. Установка выполняется в каталоге программы и не трогает данные.
- Manager и лаунчер переведены на новую версию платформы, которая получает обновления безопасности.
- Исправлены известные ошибки Manager: проверка порта веб-интерфейса, сообщение при отказе в правах администратора, очистка скачанных обновлений.
- Программа работает в сети по защищённому соединению: обычные адреса перенаправляются на защищённые. Для работы по сети в брандмауэре Windows нужно разрешить порт 443.
- При первом подключении лаунчер показывает отпечаток сертификата сервера. Его нужно сверить с отпечатком в Manager. Дальше лаунчер открывает только этот сервер и предупреждает, если сертификат сменился. Сертификат перевыпускается в Manager.
- Служба работает под отдельной учётной записью Windows с ограниченными правами. Файлы настроек и данных закрыты от других пользователей компьютера.
- Пароли камер и ключ обмена хранятся зашифрованными. После переноса настроек на другой компьютер их нужно ввести заново.
- Настройки станции, от которых зависит учёт, меняет только администратор: срок правки документа, допуски тары, пороги распознавания, длину номера вагона, минимальный груз. Оператор видит их без права изменения.
- Каждое изменение настроек станции, в том числе из Manager, попадает в историю: кто, когда, что было и что стало. История открывается в окне настроек станции.
- Права пользователя задаются только отметками в его роли. Управление ролями и обменом, правка закрытых документов и настройки станций стали отдельными правами роли.
- Пользователь не может создать роль или назначить пользователю права и станции шире своих. Последнего администратора нельзя лишить прав.
- Пользователь с ограничением по станциям видит только свои станции: в журналах, документах, фото, камерах, весах и на «Дашборде». Удаление станции из настроек не открывает ему чужие станции.
- Заблокированный пользователь перестаёт получать данные на уже открытых страницах не позже чем через 30 секунд.
- Число станций проверяется по лицензии. Станция сверх лицензии помечена в меню «нет лицензии»: её журналы открываются, но взвешивать на ней и менять её настройки нельзя.
- Лицензия продолжает действовать после замены одной-двух частей компьютера. Если оборудование изменилось сильнее, программа работает ещё 7 дней с предупреждением, за это время нужно получить новый ключ.
- Ключи лицензии, выданные для прежних версий, не подходят. Нужно прислать поставщику новый Hardware ID из Manager и получить ключ заново.
- Медленное чтение данных об оборудовании компьютера больше не задерживает запуск сервера.
- Пароли камер больше не появляются в сообщениях об ошибках и в журнале сервера.
- Просмотр камеры, снимки и запись ЖД динамики идут через одно подключение к камере. Камера меньше нагружается и не отказывает в подключении. Число одновременных просмотров одной камеры ограничено.
- Видеозахват с камер завершается вместе со службой и не остаётся работать после её остановки.
- Пароль пользователя должен быть не короче 10 символов. Чтобы сменить свой пароль, нужно ввести текущий.
- Неверные попытки входа под чужим именем больше не блокируют этому пользователю вход, а только ненадолго замедляют его.
- Нельзя завести двух действующих контрагентов с одним названием, в том числе переименованием или возвратом из архива.
- Логотип организации с ошибкой в файле не сохраняется. Если сохранить реквизиты не удалось, остаётся прежний логотип.
- Большие справочники показывают первые 5000 записей, остальные находятся поиском.
- Закрыты известные уязвимости сервера.
- Поиск в справочниках и вход в программу больше не различают заглавные и строчные русские буквы. Если внешняя база данных настроена так, что русские буквы в поиске различаются, Manager предупреждает об этом.
- Если внешняя система недоступна, например ночью, отправка результатов взвешивания повторяется, пока не пройдёт, а не прекращается через час. Отправка останавливается только при отказе получателя принять документ.
- О проблемах с обменом сообщают отметка у пункта меню «Обмен», страница обмена и Manager: есть отправки с ошибкой, отправки давно не уходят или файл настроек обмена испорчен. Все отправки с ошибкой можно повторить одной кнопкой.
- Испорченный файл настроек обмена больше не отключает обмен: сервер работает по последним исправным настройкам.
- При обмене через файл и по сети одновременно повторная попытка больше не создаёт файл заново, если он уже был передан. Добавление фото к записанному взвешиванию не отправляет его повторно.
- Копии разных видов хранятся отдельно: несколько восстановлений подряд больше не удаляют копию, снятую перед обновлением. Повторные попытки обновить базу данных не заполняют диск копиями.
- Восстановление из непригодной копии или из копии, снятой более новой версией программы, отклоняется до изменения базы данных.
- Если внешний сервер PostgreSQL новее поставляемой программы копирования, Manager показывает понятную причину, почему копия не создаётся.
- В резервный каталог больше не попадают файлы с паролями и ключами. После восстановления на другом компьютере пароли задаются заново.
- Копию базы данных по расписанию можно делать каждые несколько часов. Manager предупреждает, пока резервный каталог не задан.
- Встроенная база данных штатно останавливается при выключении Windows и при остановке службы, в том числе после её аварийного завершения. Если порт встроенной базы занят другой программой, сервер сразу показывает понятную причину.
- После обновления станции ЖД начинают записывать взвешивания, только когда база данных готова.
- Входящий обмен больше не создаёт повторяющихся контрагентов и грузов при одновременных взвешиваниях.
- Служебные журналы сервера очищаются по сроку хранения и не растут бесконечно.
- Уверенность распознавания номеров теперь показывается правильно, и порог уверенности в настройках станции работает как задумано.
- Номер вагона или контейнера с камеры, у которого не сходится контрольная цифра, больше не принимается автоматически: его проверяет оператор. Пока номер не подтверждён, по нему не подставляется тара, не ищется документ и вагон не попадает в справочник.
- Если камера не разглядела контрольную цифру контейнера, программа больше не дописывает её сама: оператор вводит номер полностью.
- ЖД статика в автоматическом режиме ждёт подтверждённого номера до конца распознавания и не записывает вагон с первым попавшимся номером. Если номер так и не подтвердился, запись сохраняется с номером на проверку.
- На ЖД погрузке, разгрузке и в ЖД динамике номер из 11 знаков вводится как номер контейнера, с буквами, как в ЖД статике.
- В журнале ЖД динамики неподтверждённый номер можно подтвердить, не меняя его.
- В ЖД динамике номер распознаётся по кадру того момента, когда вагон был над весами, поэтому на скорости в кадр не попадает следующий вагон.
- Модели распознавания, добавленные на сервер после запуска, подхватываются без перезапуска службы. Проверка распознавания из интерфейса не задерживает работу станций, распознавание меньше нагружает сервер.
- ЖД динамика больше не теряет вагоны на скорости 9–15 км/ч и на коротких вагонах. Каждый вагон попадает в журнал, а то, что программа не смогла разобрать, помечено «требует разбора». Локомотив определяется по числу осей и нагрузке.
- Вагоны ЖД динамики, взвешенные с остановкой или откатом на весах, с превышением скорости, не полностью или с нестандартным числом осей, помечаются «перевзвесить» и не выгружаются во внешние системы.
- При завершении сессии ЖД динамики оператор указывает, сколько вагонов было в составе. При открытии сессии можно указать число вагонов по накладной. Расхождение с числом записей видно в журнале.
- Режим ЖД динамики на двух платформах отключён до проверки на реальных составах: станция с ним не запускается и показывает ошибку настройки, в Manager выбирается одна платформа.
- При долгом отказе базы данных ЖД динамика продолжает принимать вагоны и записывает их, когда связь восстановится.
- Фото и номер вагона ЖД динамики снимаются в момент прохода, а не после записи в базу. Тара не подставляется по неуверенно распознанному номеру, пока оператор его не подтвердит. Метка RFID подставляется только своему вагону.
- Изменённые настройки ЖД динамики начинают действовать после прохода состава. Длина платформы и порог веса проверяются при сохранении. Вес осей округляется до деления весов.
- Лог осциллограммы ЖД динамики ограничен по размеру, хранится 90 дней и не пишется, если на диске мало места.
- На ЖД погрузке и разгрузке отключение камеры распознавания больше не останавливает взвешивание: номер вагона вводится вручную.
- Если на ЖД погрузке вагон сходил с весов или пропадала связь с весами и вес изменился, перед фиксацией оператор подтверждает, что на весах тот же вагон.
- Сессия ЖД погрузки без завершённых взвешиваний сохраняется в журнале как отменённая, а не удаляется.
- После перезапуска сервера цикл ЖД погрузки восстанавливается по тем весам, на которых уже было взвешивание, даже если набор весов в Manager изменили.
- Убрано окно выбора стороны подачи состава на ЖД погрузке: оно ни на что не влияло.
- ЖД статика на двух платформах в ручном режиме записывает текущий вес вагона, а не вес прошлого взвешивания.
- После перезапуска службы посреди состава ЖД статика продолжает нумерацию вагонов. Если на уже записанной позиции стоит вагон с другим весом или номером, станция останавливается и предлагает записать его как другой вагон.
- ЖД статика записывает вагон только при стабильном весе: если вес изменился в момент записи, станция снова ждёт стабильности. Вес берётся по устойчивому участку и округляется до деления весов.
- Светофор ЖД статики переключается сразу и не ждёт записи в базу. Зависшая запись на одной станции не останавливает другие станции.
- Режим подтверждения записи оператором ЖД статики сохраняется в сессии и действует после перезапуска службы.
- Тара в брутто ЖД статики берётся только из измеренной тары, и видно, из какого взвешивания она взята. При исправлении номера тара и нетто пересчитываются, новый вагон в сессии тары получает тару в справочнике.
- Небольшой минус около нуля на весах ЖД статики больше не вызывает аварию. Авария по отрицательному весу возникает, только если минус держится, и не повторяется на каждом кадре.
- Откат вагона после записи на ЖД статике вызывает аварию, а не повторную запись. Номер, совпадающий с предыдущим вагоном, требует подтверждения оператора. Станцию ЖД статики на четыре платформы или с несколькими весами сохранить нельзя.
- Ошибка настроек станции ЖД статики или временный сбой базы держат станцию на красном и показывают причину, а не останавливают её. Подсказки оператору показываются на русском. Светофор без подтверждения от модуля считается неисправным.
- Если весы перестали передавать данные, а связь с ними формально осталась (например, у преобразователя пропало питание), сервер через несколько секунд показывает «Нет данных от весов» и сам переподключается. Перезапускать службу не нужно.
- Перегруз и недогруз весов показываются как перегруз и недогруз, а не как 0 кг, в том числе в Manager.
- Если на терминале весов взята тара и он передаёт вес нетто, станции ЖД не записывают такой вес как брутто и сообщают об этом. На терминале нужно включить передачу брутто или режим с признаками.
- Вес становится стабильным через заданное время (по умолчанию 3 секунды) при обычной скорости передачи весов. Колебание последней цифры на одно деление стабильности не мешает.
- Перевод часов компьютера, в том числе автоматическая сверка времени, больше не вызывает на станциях ЖД ложных ошибок «Нарушен порядок времени» и «Нет свежих показаний».
- Сбой в одной из частей сервера больше не останавливает весь сервер: эта часть перезапускается сама. Если служба всё же остановилась из-за сбоя, система запускает её снова.
- Ошибки при запуске сервера, например испорченный файл настроек, теперь попадают в журнал сервера, который показывает Manager.
- Если файл настроек оборудования повреждён, сервер продолжает работать по последней исправной версии и сообщает об ошибке. Весы, считыватели и светофоры не отключаются, станции не пропадают из списка.
- Если настройки оборудования не читаются, отчёты для пользователя с ограничением по станциям не открываются, а не показывают все станции.
- Настройки оборудования с пустым или повторяющимся кодом устройства или станции не сохраняются, сервер объясняет причину.
- Светофоры ЖД статики гаснут при запуске и остановке службы и при долгой потере управления, а не остаются в последнем состоянии, например зелёными.
- После проверки модуля ввода-вывода в Manager или смены скорости порт освобождается сразу, а не после перезапуска службы. Ошибка модуля показывается сразу и с причиной.
- Протокол весов «CAS» в Manager называется «IE21.5 (SC-A1)»: это формат терминала SC-A1, с терминалами CAS он не связан.
- Лаунчер ищет сервер в сети на другом порту: прежний совпадал с портом VPN WireGuard. Сервер и лаунчер нужно обновить вместе. На сервере с несколькими сетями лаунчер получает адрес сервера в своей сети.
- В журнале сервера сообщение о подключении весов появляется, только когда весы начали передавать данные. Повторяющаяся ошибка связи не засоряет журнал.
- Исправлены известные ошибки чтения весов.

## 1.0.14

- Сервер каждый день делает резервную копию базы. Время копии и сколько копий хранить задаются в Manager. Копию можно дублировать в другую папку на другом диске или в сетевую, с проверкой, что она записалась целиком. Вместе с копией сохраняются настройки, лицензия и ещё не записанные в базу проходы ЖД динамики.
- В Manager появилась кнопка «Сделать копию сейчас». В списке копий видно, когда и какой версией снята копия. Manager предупреждает, если копия не снималась больше суток или не попала в резервную папку.
- Повреждённая резервная копия не восстанавливается, база остаётся как была.
- Для отката на предыдущую версию нужна копия, снятая перед обновлением. Ежедневная копия другой версии для отката не подходит.
- Числа в отчётах Excel, PDF и CSV округляются одинаково, итоги совпадают. В CSV дробная часть пишется через запятую, и Excel больше не превращает числа в даты.
- Отчёты в Excel формируются быстрее. Если большие отчёты выгружают сразу несколько человек, сервер готовит не больше двух файлов одновременно, остальные ждут своей очереди.
- Исправлены известные ошибки веб-интерфейса.
- Повышена безопасность обработки снимков с камер. Распознавание номеров и подпись на фото работают как прежде, снимки с подписью занимают меньше места.
- В папках сервера и лаунчера появился файл со списком сторонних компонентов программы и их лицензиями.
- Если сервер не ответил вовремя или прислал повреждённый ответ, действие больше не выглядит выполненным. Если так случилось при сохранении, программа предупреждает, что результат неизвестен, и просит проверить его, прежде чем повторять.
- Короткий обрыв связи во время сохранения больше не прячет это предупреждение за окном «Нет связи с сервером».
- Если журнал сессий ЖД статики не загрузился, страница показывает ошибку, а не пустой журнал. Показания весов при потере связи не остаются на экране.
- Ошибки, которые раньше пропадали молча, теперь показываются уведомлением.
- Лаунчер открывает окно сразу и ищет сервер в фоне, поиск можно отменить. Если сервер доступен по прежнему адресу, лаунчер подключается быстрее.
- Manager открывается на сервере в одном экземпляре. Повторный запуск показывает уже открытое окно.
- Если результат обслуживания не подтвердился, администратор может завершить операцию, указав причину. Причина и учётная запись сохраняются в журнале обслуживания.
- После неудачной установки обновления можно восстановить базу из резервной копии или откатиться на предыдущую версию.
- Первая настройка базы, демо-режим, активация лицензии и удаление программы больше не выполняются одновременно с другим обслуживанием. Для удаления программы сначала остановите службу в Manager.
- Обслуживание сервера со станцией «Авто» больше не требует заранее останавливать службу: станция встаёт на паузу между машинами.
- При остановленной службе Manager перед восстановлением базы или обновлением сам проверяет незавершённые ЖД-сессии. Если проверить нельзя, он спрашивает подтверждение.
- Manager не затирает настройки, которые оператор изменил в веб-интерфейсе после открытия окна, и предлагает перечитать конфигурацию.
- Обновление устанавливается только с подписью издателя, в том числе из файла. При установке с флешки рядом с установщиком должен лежать его файл подписи.
- Откат на предыдущую версию выполняется одной командой вместе с восстановлением резервной копии базы. Старую версию без копии базы установить нельзя.
- Перед обновлением Manager проверяет, хватит ли места на диске.
- Ошибка в форме настроек сразу показывается как отказ и не оставляет сервер заблокированным.
- В ЖД динамике вагон, который не удалось сохранить из-за ошибки в самой записи, больше не останавливает станцию навсегда. Приём останавливается, на странице появляется список таких вагонов для повторного взвешивания, после этого приём можно возобновить и закрыть сессию.
- В ЖД динамике незавершённый вагон при обрыве связи с весами сразу помечается неполным, а не только при закрытии сессии.
- В ЖД динамике начать взвешивание можно, когда данные сервера лежат на сетевом пути. Если свободное место узнать не удалось, оператор видит понятное сообщение.
- Повышена надёжность сохранения проходов ЖД динамики при сбоях и большой очереди.
- В ЖД погрузке и разгрузке повторный запуск цикла после обрыва связи продолжает уже начатый цикл, а не открывает второй.
- В документе погрузки/разгрузки реквизиты берутся на момент фиксации веса. Если груз переименовали до второго взвешивания, документ не меняется.
- В ЖД статике отмена сессии, подтверждение и отмена подготовки относятся только к той сессии, с которой их отправили. Запоздавшее нажатие не затронет новую сессию.
- В ЖД динамике номер, распознанный камерой с опозданием, не заменяет номер, введённый оператором, а фото вагона не теряются.
- Повышена надёжность сохранения в ЖД погрузке, разгрузке и статике при сбоях связи с базой.
- Если связь с базой оборвалась во время сохранения, программа пишет, что результат не подтверждён, а не сообщает о конфликте с уже сохранённой записью.
- Журналы сессий ЖД динамики и погрузки/разгрузки показывают груз и контрагентов на дату взвешивания, даже если их потом переименовали.
- Manager не перезаписывает данные организации, если их изменили после открытия формы.
- Авто взвешивание на новой установке больше не падает из-за недостающих полей в базе.
- Повторное нажатие или обрыв связи при сохранении веса в ЖД статике, погрузке/разгрузке и динамике не создают второе взвешивание. Если неизвестно, сохранилась ли запись, оператор видит это и повторяет сохранение без дубля. Закрытие и отмена относятся к той сессии, из которой их отправили.
- После перезапуска ЖД статики последний сохранённый вагон нужно сверить и сбросить, только потом взвешивать следующий.
- В ЖД погрузке и разгрузке вес фиксируется, только когда каждая платформа и их сумма стабильны. Колебание между опросами не даёт сохранить вес ручным нажатием.
- Замолчавший терминал больше не выглядит исправным: старый вес не выдаётся за свежий, фиксация в таком случае запрещена.
- В ЖД динамике очередь проходов ограничена. При сбое базы или диска, переполнении очереди и после перезапуска приём составов останавливается до кнопки «Возобновить приём». Перед возобновлением сервер проверяет базу, диск и пустые платформы. Черновики прерванного прохода помечаются неполными.
- Документы ЖД статики, погрузки/разгрузки и динамики хранят реквизиты на момент взвешивания. Переименование груза, контрагента или организации старые акты и отчёты не меняет. Для записей, сделанных до этого, документ предупреждает, что исторических реквизитов нет.
- Ручная правка реквизитов и номера требует указать причину. В карточке статики и ведомости погрузки/разгрузки есть «История документа»: кто, когда, почему и что было до и после.
- В справочниках ЖД-грузов, контрагентов и лиц одновременная правка не затирается. Введённые данные остаются в форме, актуальная запись показывается рядом, заменить форму можно только явно. Основной ЖД-груз может быть только один.
- В Manager появилась карточка «Обслуживание сервера». Перезапуск, остановка и установка службы, восстановление базы, обновление и сохранение настроек идут по одной операции за раз. На время обслуживания сервер не принимает изменения и не начинается при открытых ЖД-сессиях. Результат проверяется и после перезапуска Manager.
- Установщик обновления, запущенный в обход Manager во время обслуживания, отказывается работать. Обновление без опубликованной контрольной суммы не устанавливается.
- Резервная копия базы появляется в списке только после того, как полностью создана.
- Лаунчер находит сервер, даже если база ещё не готова.
- Если страница не открылась из-за ошибки, вместо пустого экрана показывается сообщение и напоминание проверить журнал перед повтором. Сообщение о потере связи с сервером стало понятнее.
- В выгрузке CSV текст, похожий на формулу, Excel не выполняет.
